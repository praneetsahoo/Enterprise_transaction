## Why each resource exists

| Resource | Purpose |
|---|---|
| VPC + subnets | Network boundary; the database lives in subnets with no internet route |
| 2 private subnets | RDS requires subnets in at least two availability zones |
| Internet gateway (public subnet only) | Lets EC2 install packages and reach S3/SSM/CloudWatch |
| `payrecon-app-sg` | Only port 80 inbound, for the password-protected dashboard (added in Phase 9). No SSH |
| `payrecon-db-sg` | MySQL reachable only from the app server's security group |
| S3 bucket | Raw files land here first; DLQ and processed copies kept next to them |
| SSM parameters | Encrypted DB passwords, generated by AWS, read by EC2 at runtime |
| IAM role | Gives EC2 temporary credentials with only the access listed below |
| CloudWatch | Central logs; alarm when the pipeline logs an ERROR |

## IAM role `payrecon-ec2-role` (least privilege)

| Allowed | On |
|---|---|
| `s3:ListBucket` | the payrecon bucket |
| `s3:GetObject`, `s3:PutObject` | `raw/*`, `processed/*`, `dlq/*` only |
| `ssm:GetParameter` | `/payrecon/db/*` and `/payrecon/dashboard/*` only |
| **Deny** `ssm:GetParameter(s/ByPath/History)` | everything outside `/payrecon/*` — needed because the AWS-managed `AmazonSSMManagedInstanceCore` policy allows `ssm:GetParameter` on `*` (found by failure drill D4; verified with a real call — the IAM policy simulator mis-reports this `NotResource` deny) |
| `logs:CreateLogStream`, `logs:PutLogEvents` | `/payrecon/*` log groups only |
| `AmazonSSMManagedInstanceCore` | lets us administer the server without SSH |

## Database users

| User | Used by | Rights |
|---|---|---|
| `payrecon_admin` | one-time setup only (`infra/bootstrap_db.py`) | RDS master |
| `payrecon_app` | the pipeline and dashboard | `payrecon` database only, **TLS required** |

## Scripts

| Script | Runs where | Does |
|---|---|---|
| `infra/user_data.sh` | EC2 first boot | Python 3.11, git clone, virtualenv, RDS CA bundle |
| `infra/bootstrap_db.py` | EC2, once | Creates the least-privilege `payrecon_app` user |
| `infra/deploy.sh` | EC2, after each push | user, settings file, systemd service, CloudWatch agent, health check |
| `infra/run_pipeline.sh` | EC2, on demand | pipeline + reports as the `payrecon` user |
| `infra/check_connectivity.py` | EC2 | 8 checks: SSM, RDS TLS, no-TLS refused, private IP, S3 allow/deny, CloudWatch |
