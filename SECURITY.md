# PayRecon — security summary

Checked in Phase 12 with evidence: `infra/security_check.sh` (server), `tests/test_security.py`,
`infra/failure_drills.sh`, and a read-only audit of the AWS configuration.

| Area | Control | Evidence |
|---|---|---|
| Secrets | DB + dashboard passwords generated by AWS, stored as SSM SecureString, read at runtime by the EC2 role | real secret values searched in git history, working tree, logs, journal, /etc: 0 hits |
| Git | `.env`, keys, data files git-ignored; no AWS keys anywhere | history scan + `test_no_credentials_in_tracked_files` |
| IAM | role: own bucket folders, own parameters, own log groups; **explicit deny** on any parameter outside `/payrecon/*` (the AWS-managed SSM policy allows `*`) | failure drills D4 (AccessDenied) and D5 (other bucket denied) |
| Network | RDS private (no public IP, private subnets); DB port only from the app security group; app server only port 80; no SSH key, sshd disabled, admin via SSM | AWS audit; listening ports = 80 only |
| Database | TLS required for **both** users (`REQUIRE SSL`); app user limited to `payrecon.*` (no DROP/FILE/SUPER/GRANT); storage encrypted; deletion protection on | non-TLS logins refused (1045); `SHOW GRANTS` |
| Data | S3: public access blocked, SSE, versioning, non-TLS requests denied; DECIMAL money; schema never drops | AWS audit |
| Host | IMDSv2 only; encrypted disk; dashboard runs as `payrecon` (no shell), not root; settings file 640 | security_check.sh |
| Application | all SQL values bound parameters; no `assert` for business checks; 50 MB upload limit, 200 MB file limit; malformed rows to DLQ | bandit + AST tests |
| Dashboard | password login (constant-time compare, 1 s delay per failure); XSRF on; downloads neutralise spreadsheet formulas; data values escaped in formatted text | test_security.py, test_dashboard.py |
| Monitoring | every failure logged as ERROR → CloudWatch metric → alarm | alarm fired in drills |
| Dependencies | `pip-audit`: no known vulnerabilities | security_check.sh |

## Known gaps (accepted for the hackathon, with the production fix)

| Gap | Production fix |
|---|---|
| Dashboard is HTTP, not HTTPS | Application Load Balancer + ACM certificate (or SSM port-forwarding, no public port) |
| Single shared dashboard password | Streamlit OIDC login (`st.login`) or Cognito, per-user roles |
| No CloudTrail trail (90-day event history only) | Organisation trail to an S3 bucket |
| RDS single-AZ, 1-day backups | Multi-AZ, 7–35 day backups |
| No alarm notification target | SNS topic → email / Slack on `payrecon-pipeline-errors` |
